# Ent 性能基准测试工具

这是一个用于测试 Ent 与 IBM DB2 数据库性能的基准测试工具。它提供了多种测试场景和详细的性能指标报告，与 GORM 版本保持相同的测试场景和报告格式。

## 功能特性

- ✅ **多种测试场景**: 创建、读取、更新、删除、批量操作、混合工作负载
- ✅ **并发测试**: 支持多线程并发测试
- ✅ **详细指标**: 延迟统计(毫秒)、吞吐量、内存使用等
- ✅ **灵活配置**: 支持命令行参数配置
- ✅ **报告输出**: JSON 格式报告和控制台输出
- ✅ **预热机制**: 测试前预热数据库连接

## 快速开始

### 1. 构建基准测试程序

```bash
cd entdemo/benchmark/main
chmod +x build.sh
./build.sh build
```

### 2. 运行基准测试

```bash
# 运行所有测试
./build.sh all

# 或者单独运行
./build.sh run
```

### 3. 使用命令行参数

```bash
# 直接运行基准测试程序
./benchmark_main -threads 20 -test-time 60s -batch-size 50 -report my_report.json

# 使用自定义数据库连接
./benchmark_main -dsn "HOSTNAME=myserver;DATABASE=mydb;PORT=50001;UID=myuser;PWD=mypassword;AUTHENTICATION=SERVER;CurrentSchema=MYSCHEMA"

# 可用参数:
# -threads: 并发线程数 (默认: 1)
# -iterations: 每个线程的迭代次数 (默认: 1)
# -warmup: 预热时间 (默认: 5s)
# -test-time: 测试时间 (默认: 5s)
# -batch-size: 批量操作大小 (默认: 100)
# -report: 报告文件名 (默认: benchmark_report.json)
# -dsn: 数据库连接字符串 (默认: IBM DB2 连接字符串)
```

## 测试场景

### 1. 创建性能测试
- 测试单条记录的创建性能
- 测量创建操作的延迟和吞吐量

### 2. 读取性能测试
- 测试单条记录的读取性能
- 需要预先创建测试数据

### 3. 更新性能测试
- 测试单条记录的更新性能
- 每次更新增加年龄字段

### 4. 删除性能测试
- 测试单条记录的删除性能
- 先创建后删除测试记录

### 5. 批量操作测试
- 测试批量创建操作的性能
- 可配置批量大小

### 6. 混合工作负载测试
- 模拟真实工作负载
- 按比例混合 CRUD 操作

## 性能指标

每个测试场景都会生成以下性能指标：

- **总操作数**: 测试期间完成的操作总数
- **总时间**: 测试运行的总时间(毫秒)
- **每秒操作数 (OPS)**: 系统吞吐量
- **平均延迟**: 操作的平均响应时间(毫秒)
- **最小延迟**: 最快操作的响应时间(毫秒)
- **最大延迟**: 最慢操作的响应时间(毫秒)
- **P95延迟**: 95% 操作的响应时间(毫秒)
- **P99延迟**: 99% 操作的响应时间(毫秒)
- **错误数**: 测试期间发生的错误数量
- **内存使用**: 测试期间的内存使用量

## 配置说明

### 数据库配置

数据库连接配置在 `dbhelper.go` 中：

```go
func GetCrudDb(dsn string) *hzwent.Client {
    client, err := hzwent.Open("go_ibm_db", dsn)
    if err != nil {
        log.Fatalf("failed opening connection to %s: %v", "go_ibm_db", err)
    }
    return client
}
```

请根据您的环境修改连接字符串。

### 测试配置

可以通过命令行参数或修改源代码来调整测试配置：

- **线程数**: 控制并发程度
- **测试时间**: 控制测试持续时间
- **批量大小**: 控制批量操作的大小
- **预热时间**: 确保数据库连接池已预热

## 与 GORM 版本的比较

这个 Ent 版本与 GORM 版本具有相同的功能：

- ✅ 相同的测试场景和指标
- ✅ 相同的命令行参数
- ✅ 相同的报告格式
- ✅ 相同的时间单位(毫秒)

主要区别：
- 使用 Ent 框架而不是 GORM
- 使用不同的数据库操作 API
- 生成的可执行文件大小不同

## 最佳实践

1. **环境准备**
   - 确保数据库服务器正常运行
   - 检查网络连接稳定性
   - 准备足够的测试数据

2. **测试策略**
   - 从低并发开始，逐步增加
   - 每次测试后清理测试数据
   - 多次运行取平均值

3. **结果分析**
   - 关注 P95 和 P99 延迟
   - 比较不同配置下的性能差异
   - 监控系统资源使用情况

## 故障排除

### 常见问题

1. **连接失败**
   - 检查数据库连接字符串
   - 确认网络连通性
   - 验证数据库用户权限

2. **性能异常**
   - 检查数据库负载
   - 监控系统资源
   - 调整连接池配置

3. **内存泄漏**
   - 监控内存使用趋势
   - 检查数据库连接是否正常关闭
   - 分析堆内存使用情况

## 扩展开发

2. 在主函数中调用新的测试方法
3. 更新报告生成逻辑

### 自定义性能指标

1. 修改 `BenchmarkResult` 结构体
2. 更新性能计算逻辑
3. 调整报告输出格式
